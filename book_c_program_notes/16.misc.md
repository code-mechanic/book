## Compound assignment / Short hand assignment operator

```c
// Compound Assignment Operators and Precedence Traps

#include <stdio.h>

int main() {
    // ==========================================
    // 1. Compound / Short Hand Assignment
    // ==========================================
    /*
       Compound assignment (or short hand assignment) reduces redundancy
       when a variable is being updated based on its own current value.
    */
    int avgsalofswemp = 5000;

    // Long form:
    avgsalofswemp = avgsalofswemp + 1000;
    // Short hand:
    avgsalofswemp += 1000;

    int x = 0;
    x += 3;             // Expands to: x = x + 3;

    int a = 10, b = 2;
    // Standard Arithmetic Short Hands:
    a -= b;             // -> a = a - b;
    a %= 5;             // -> a = a % 5;
    a *= 7;             // -> a = a * 7;
    a /= 2;             // -> a = a / 2;

    // Bitwise Short Hands:
    a <<= 3;            // -> a = a << 3;
    a >>= 2;            // -> a = a >> 2;
    a &= 1;             // -> a = a & 1;
    a ^= b;             // -> a = a ^ b;

    // ==========================================
    // 2. Syntax Traps (Compile Errors & Logic Traps)
    // ==========================================

    /*
       TRAP 1: Unary operators cannot be compounded.
       Attempting `a ~= 2;` generates a Compile Error (C.E).
    */

    /*
       TRAP 2: Confusing assignment with relational operators.
       `a <= 3` is a relational check (Less than or equal to), NOT an assignment.
       It does NOT expand to `a = a < 3` (crossed out with an 'X' on the board).
    */

    // ==========================================
    // 3. The Right-Hand Side (RHS) Precedence Trap
    // ==========================================
    a = 10;

    /*
       Assignment operators (=, +=, *=, etc.) have the lowest precedence.
       The compiler evaluates the ENTIRE right side of the equation BEFORE
       applying the compound operator to the left side.
    */
    a *= 10 + 2;

    /*
       This translates implicitly to: a = a * (10 + 2)
       Calculation: 10 * 12 = 120

       It does NOT evaluate strictly left-to-right as (a * 10) + 2 = 102.
    */
    printf("Result: %d\n", a);                  // Output: 120

    return 0;
}
```

### Chained Compound Assignment and Right-to-Left Associativity

```c

#include <stdio.h>

int main() {
    // Initializing variables in memory
    int a = 10, b = 5, c = 8, d = 15;

    // ==========================================
    // Chained Assignment Evaluation
    // ==========================================
    /*
       Assignment operators (=, +=, -=, etc.) share the same precedence level
       but have Right-to-Left associativity. When chained together, the compiler
       evaluates the expression starting from the far right and cascades the
       results backward to the left.
    */
    a += b *= c -= d /= 7;

    // Final state of the variables based on memory boxes:
    printf("a = %d\n", a);                      // Output: 40
    printf("b = %d\n", b);                      // Output: 30
    printf("c = %d\n", c);                      // Output: 6
    printf("d = %d\n", d);                      // Output: 2

    return 0;
}

/*
===============================================================================
Right-to-Left Execution Visualization
===============================================================================

Step 1:
  d /= 7;
  d = 15 / 7 => 2 (Integer division drops the remainder)
  Current Expression State: a += b *= c -= (2)
  Memory update: d becomes 2 (crossed out 15)

Step 2:
  c -= 2;
  c = 8 - 2 => 6
  Current Expression State: a += b *= (6)
  Memory update: c becomes 6 (crossed out 8)

Step 3:
  b *= 6;
  b = 5 * 6 => 30
  Current Expression State: a += (30)
  Memory update: b becomes 30 (crossed out 5)

Step 4 (Outer-most left box):
  a += 30;
  a = 10 + 30 => 40
  Memory update: a becomes 40 (crossed out 10)
*/
```

## Command line arguments

```c
// Command Line Arguments (CLA)

#include <stdio.h>

// ==========================================
// 1. Passing Arguments to main()
// ==========================================
/*
   Definition: Passing arguments main function is called CLA.

   Instead of a standard void main(), we define two specific parameters
   to capture inputs passed directly from the operating system when the
   program is launched.
*/
int main(int argc, char *argv[]) {

    // argc -> argument count
    // Tracks the total number of arguments passed (including the program name itself).

    // argv -> argument values / argument vector
    // An array of character pointers (strings) holding the actual text passed.

    printf("Argument Count (argc): %d\n", argc);

    // Loop through the argument vector to display values
    for(int i = 0; i < argc; i++) {
        printf("argv[%d]: %s\n", i, argv[i]);
    }

    return 0;
}

/*
===============================================================================
Normal Functions vs. Main Function
===============================================================================

Normal user-defined functions are called explicitly from within your code:

  void test(int x, int y) { ... }
  test(10, 20);

The `main` function is fundamentally different because it is invoked by the OS.
you cannot just write `main(10, 20);` inside your program to pass it values.

Instead, these arguments are supplied externally via the command line execution.

===============================================================================
Compilation Targets and Execution (Bottom Board)
===============================================================================

When `test.c` is compiled, it generates an OS-specific executable file:

  WIN (Windows): Generates `test.exe`
  Execution: > test.exe 10 20

  LINUX: Generates `test` => `test.elf`
  Execution: $ ./test 10 20
*/

```

When you execute `./test 10 20` in a Linux terminal, the OS automatically parses that command string, sets `argc` to 3, and populates the `argv` array with `["./test", "10", "20"]`.

### Command Line Arguments, Pointer Arithmetic, and Memory Architecture

```c
#include <stdio.h>

// ==========================================
// 1. Array of Pointers vs Double Pointers
// ==========================================
/*
   In C, an array of pointers passed as a parameter `char *argv[]`
   decays into a double pointer `char **argv`.
*/
int main(int argc, char **argv) {

    // The min value in argc is 1, as it always includes the program name.
    int i = 0;

    // Loop through the argument vector and print each string.
    for(i = 0; i < argc; i = i + 1) {
        puts(argv[i]);
    }

    return 0;
}

/*
===============================================================================
2. Command Prompt Execution & String Grouping
===============================================================================

Standard Execution:
D:\src> test.exe hello bye

The OS parses this by spaces, resulting in an argc of 3.
Array indexing maps directly to pointer arithmetic offsets:
  argv[0] -> *(argv+0) -> test.exe
  argv[1] -> *(argv+1) -> hello
  argv[2] -> *(argv+2) -> bye

Grouped Execution:
D:\src> test.exe "foot ball"

By wrapping text in double quotes, the space is ignored as a delimiter,
resulting in an argc of 2.

===============================================================================
3. Runtime Memory Map and Double Pointer Mechanics
===============================================================================

.-----------------------------------------------.
|      +----------+   +-------+   +-----+       |
|      | test.exe |   | hello |   | bye |       |
|      +----------+   +-------+   +-----+       |
|             ^         ^         ^             |
|            500       600       700            |
|             |         |         |             |
|          +-------+-------+-------+            | } CLA
|  .-----> |  500  |  600  |  700  |            |
|  |       +-------+-------+-------+            |
|  |         100      102     104               |
|--|--------------------------------------------|
|  |                   Stack                    |
|  |                                            |
|  |       argc             argv                |
|  |      +---+            +-----+              |
|  |      | 3 |            | 100 |              |
|  |      +---+            +-----+              |
|  '--------------------------'                 |
|-----------------------------------------------|
|                      heap                     |
|-----------------------------------------------|
|                       Ds                      |
|-----------------------------------------------|
|                      Bss                      |
|-----------------------------------------------|
|                       RO                      |
|-----------------------------------------------|
|                       CS                      |
'-----------------------------------------------'

Inside the Stack during execution of `test.exe hello bye`:
- The variable `argc` holds the integer 3.
- The double pointer `argv` holds the base address 100.
- At address 100, an array of pointers exists containing the addresses [ 500 | 600 | 700 ].
- Those addresses point to the physical memory locations of the string literals:
  500 -> "test.exe", 600 -> "hello", 700 -> "bye".
*/
```

## Function pointers

```c
// Function Pointers and Indirect Invocation

#include <stdio.h>

// ==========================================
// 1. Definition & Basic Syntax
// ==========================================
/*
   Function Pointer : a pointer which contains fn address.
*/
void fun() {
    printf("hello fun\n");
}

void execute_basic_pointer() {
    /*
       pf is a pointer to fn whose return type is void.
       The parentheses around (*pf) are mandatory to bind the asterisk
       to the variable name rather than the return type.
    */
    void (*pf)();

    pf = fun;
    pf();                                       // Outputs: hello fun
}

// ==========================================
// 2. Function Pointers with Arguments
// ==========================================
void sum(int x, int y) {
    printf("%d\n", x + y);
}

void execute_parameter_pointer() {

    // fp is a pointer to a fn whose prototype it takes 2 int and return void.
    void (*fp)(int, int);

    fp = sum;
    fp(10, 20);
}
```

### Return Values, Callbacks, and Complex Declarations

```c

#include <stdio.h>

// ==========================================
// 1. Returning Values via Function Pointers
// ==========================================
int sum(int a, int b) {
    return a + b;
}

void execute_return_pointer() {
    int (*pf)(int, int);
    int res = 0;

    pf = sum;

    // The pointer executes the function and captures the returned integer
    res = pf(10, 20);

    printf("%d", res);                          // Outputs: 30
}

// ==========================================
// 2. Passing Pointers as Arguments (Callbacks)
// ==========================================
/*
   Instead of hardcoding which function to call, we can pass a function pointer
   into another function. In embedded systems, this is known as a "Callback"
   and is heavily used for hardware interrupts and RTOS timers.
*/

// avg takes a function pointer 'k' (which must take two ints and return an int)
int avg(int (*k)(int, int)) {
    int i;
    // Executes whatever function was passed in via 'k'
    i = k(10, 20);
    return i / 2;
}

void execute_callback() {
    int res;

    // We pass the 'sum' function itself as an argument to 'avg'
    res = avg(sum);

    // Execution flow: avg -> k(10,20) -> sum(10,20) returns 30 -> 30/2 returns 15
    printf("%d\n", res);
}
```

### Understanding of declaring function pointer syntax

```c
/*
   Declaring a pointer for a function that returns a pointer can look messy.
   simple trick: take the prototype, isolate the
   function name, and replace it with (*pointer_name).
*/

// Original Function:
void *test(int x, char *y) {
    return NULL;
}

void demonstrate_complex_declaration() {
    // Step 1: Write the raw prototype
    // void *test(int, char *);

    // Step 2: Replace 'test' with '(*fp)'
    void *(*fp)(int, char*);

    // Now fp is a valid pointer for the test function
    fp = test;
}
```

### Arrays of Function Pointers

```c
#include <stdio.h>

// ==========================================
// 1. Defining the Target Functions
// ==========================================
void sum(int x, int y) {
    printf("%d\n", x + y);
}
void diff(int x, int y) {
    printf("%d\n", x - y);
}
void prod(int x, int y) {
    printf("%d\n", x * y);
}
void div(int x, int y) {
    printf("%d\n", x / y);
}

int main() {
    // ==========================================
    // 2. The Redundant Way: Individual Pointers
    // ==========================================
    /*
       If you have multiple functions with the exact same signature (return type
       and parameters), declaring individual function pointers clutters memory
       and code.
    */
    void (*fp1)(int, int);
    void (*fp2)(int, int);
    void (*fp3)(int, int);
    void (*fp4)(int, int);

    fp1 = sum;
    fp2 = diff;
    fp3 = prod;
    fp4 = div;

    fp1(10, 20);

    // ==========================================
    // 3. The Efficient Way: Array of Pointers
    // ==========================================
    /*
       By clustering these into an array, you can index into the functions
       dynamically. The syntax groups the array size `[4]` immediately next
       to the pointer name inside the parentheses: `(*fp[4])`.
    */
    void (*fp[4])(int, int);

    fp[0] = sum;
    fp[1] = diff;
    fp[2] = prod;
    fp[3] = div;

    // Executes the 'sum' function via index 0
    fp[0](10, 20);

    return 0;
}
```

This specific structure—the array of function pointers—is the architectural foundation for two major concepts in embedded software.

First, it is how you build a **Dispatch Table** or **State Machine**. Instead of writing massive `switch/case` statements to handle different operational states, you just pass an integer state ID directly into the array index (e.g., `fp[current_state]()`).

Second, this is the exact memory construct used for the **Interrupt Vector Table (IVT)** on ARM Cortex-M processors (like STM32 or TI MCU). The hardware expects a literal array of function pointers stored at a specific memory address; when a hardware interrupt fires, the CPU automatically indexes into that array to find the address of the correct Interrupt Service Routine (ISR) and executes it.

### Simplifying Function Pointers with typedef

```c
#include <stdio.h>

void sum(int x, int y) {
    printf("%d", x + y);
}
void diff(int x, int y) {
    printf("%d", x - y);
}
void prod(int x, int y) {
    printf("%d", x * y);
}
void div_fn(int x, int y) {
    printf("%d", x / y);
}

// ==========================================
// Function Pointer typedef
// ==========================================
/*
   `typedef` is applied to the function pointer signature.
   This aliases the complex syntax into a single, clean type identifier: `fp`.
*/
typedef void (*fp)(int, int);

int main() {
    // Declaring individual function pointers is now as simple as declaring standard variables:
    fp fp1, fp2, fp3, fp4;

    fp1 = sum;
    fp2 = diff;
    fp3 = prod;
    fp4 = div_fn;

    fp1(10, 20);

    // Declaring an array of function pointers becomes drastically cleaner:
    fp fp_array[4];

    fp_array[0] = sum;
    fp_array[1] = diff;

    fp_array[0](10, 20);

    return 0;
}
```

By aliasing the complex signature into a single `fp` type, the code becomes highly scalable and
readable. When developing a cross-platform architecture, raw function pointers are rarely
exposed in the application layer. Instead, HAL structures and RTOS APIs use `typedef` to define
standard callback signatures (e.g., `typedef void (*TimerCallback_t)(void);`). This ensures
that application developers can pass their hardware-specific functions cleanly into the
abstraction layer without wrestling with nested asterisk syntax.

### Simplifying Callbacks with typedef

```c
#include <stdio.h>

// ==========================================
// 1. Define the Function Pointer Alias
// ==========================================
/*
   We define 'Pf' as an alias for any function that takes two integers
   and returns an integer.
*/
typedef int (*Pf)(int, int);

// ==========================================
// 2. Define the Target Function
// ==========================================
int sum(int a, int b) {
    return a + b;
}

// ==========================================
// 3. The Old Way vs. The Clean Way
// ==========================================
/*
   int avg(int (*pf)(int,int)) {
   }

   By using the typedef, the callback parameter becomes as readable as
   passing a standard integer. 'Pf' is the type, 'pf1' is the variable.
*/
int avg(Pf pf1) {

    // We can now execute the callback internally
    int total = pf1(10, 20);
    return total / 2;
}

int main() {
    // 4. Executing the Callback
    int result = avg(sum);

    printf("Result: %d\n", result);
    return 0;
}
```

### OS Thread Creation and Callback Handlers

```c
#include <stdio.h>

// ==========================================
// 1. The Callback Handler (Application Logic)
// ==========================================
/*
   This is the user-defined function containing the task instructions.
   as the "Call Back handler(fn)".
*/
void test() {
    // Execute task code
    printf("Thread is executing...\n");
}

// ==========================================
// 2. The OS API (Kernel Logic)
// ==========================================
/*
   This represents the internal operating system API. It accepts a function
   pointer 'fp' returning void.
*/
void pthread_create(void (*fp)()) {

    // "OS is in a process of creating a thread."
    // Internally, the OS sets up the stack and context for the new thread.

    // The OS executes the passed callback pointer to run the thread logic
    fp();
}

// ==========================================
// 3. Application Entry Point
// ==========================================
int main() {

    // We pass the 'test' function directly into the OS API.
    pthread_create(test);

    return 0;
}

```

### Standard Library Callbacks and Generic Pointers

```c
#include <stdio.h>
#include <stdlib.h>                             // qsort => predefined (lib) stdlib.h

// ==========================================
// 1. Custom Comparison Callbacks
// ==========================================
/*
   To make a sorting algorithm completely generic, it cannot know the data type
   it is sorting in advance. It uses void pointers (void *), which can hold any
   memory address but cannot be dereferenced directly.
*/
int cmpint(void *a, void *b) {
    // 1. Cast the generic void* to a specific int* -> (int*)a
    // 2. Dereference the pointer to get the actual value -> *(int*)a
    // 3. Subtract to return a positive, negative, or zero integer
    return *(int*)a - *(int*)b;
}

int cmpfloat(void *a, void *b) {
    return *(float*)a - *(float*)b;
}

// ==========================================
// 2. The qsort Library Function
// ==========================================
int main() {

    int iarr[] = {35, 15, 25, 78, 96, 2};
    float farr[] = {6.5, -2.5, -8.12, 9.17};

    /*
       qsort takes 4 arguments:
       1. Base address of the array
       2. Number of elements
       3. Size of a single element in bytes
       4. Function pointer to the comparison callback
    */
    qsort(iarr, 6, sizeof(int), cmpint);
    qsort(farr, 4, sizeof(float), cmpfloat);

    return 0;
}
```

## Comma operator

```c
// The Comma Operator and Left-to-Right Evaluation

#include <stdio.h>

int main() {
    // ==========================================
    // 1. Variable Initialization
    // ==========================================
    int a = 5, b = -3, c = 0, d = 2;

    // ==========================================
    // 2. The Comma Operator Mechanics
    // ==========================================
    /*
       how the comma operator behaves?

       When a series of expressions is separated by commas, the compiler evaluates
       them strictly sequentially from Left to Right.

       Crucially, it discards the results of every expression except the very last
       one.
    */

    // Evaluating the condition: if (5, -3, 0, 2)
    // Step 1: 'a' (5) is evaluated and discarded.
    // Step 2: 'b' (-3) is evaluated and discarded.
    // Step 3: 'c' (0) is evaluated and discarded.
    // Step 4: 'd' (2) is evaluated and returned as the final condition.

    if (a, b, c, d) {
        printf("hello");
    } else {
        printf("hai");
    }

    // Because the final evaluated expression 'd' is 2 (a non-zero truthy value),
    // the true branch executes.
    // Final Output written on board: hello

    return 0;
}
```

The comma operator is a frequent source of logic bugs because it is visually identical to the
comma used for separating function arguments or variable declarations, but it acts entirely
differently when used inside an expression sequence.

### Comma Operator vs. Precedence Traps and Code Compression

```c
#include <stdio.h>

void execute_comma_traps() {
    // ==========================================
    // 1. The Precedence Trap
    // ==========================================
    int a;
    /*
       The assignment operator (=) has HIGHER precedence than the comma operator (,).
       The compiler reads this as: (a = 5), 3, 2;
       It assigns 5 to 'a', then evaluates and discards 3 and 2.
    */
    a = 5, 3, 2;
    printf("%d\n", a);                          // Outputs: 5

    // ==========================================
    // 2. Overriding with Parentheses
    // ==========================================
    int b;
    /*
       Parentheses force the comma operator to evaluate first.
       (5, 3, 2) evaluates left-to-right, discarding 5 and 3, returning 2.
    */
    b = (5, 3, 2);
    printf("%d\n", b);                          // Outputs: 2

    // Combining precedence and parentheses:
    int c;
    c = (4, 5, 6), (7, 8, 9);
    // Evaluates as: (c = (4,5,6)), (7,8,9); -> (c = 6), 9;
    printf("%d\n", c);                          // Outputs: 6

    // ==========================================
    // 3. The Declaration Trap (Compile Error)
    // ==========================================
    /*
       int d = 5, 3, 2; // C.E : ES (Compile Error: Expected Semicolon)

       Why? In a variable declaration, the comma is a SEPARATOR, not an operator.
       The compiler expects a new variable identifier after the comma (like `d=5, e=3`),
       so seeing a raw '3' triggers a syntax error.

       Fix: Wrap it in parentheses to force it into an expression.
    */
    int d = (5, 3, 2);
    printf("%d\n", d);                          // Outputs: 2

    // ==========================================
    // 4. Sequential Evaluation with Increments
    // ==========================================
    int x = 5, y;
    /*
       Evaluating: (++x, x++, x++)
       1. ++x : Pre-increment. x becomes 6. Expression returns 6.
       2. x++ : Post-increment. Expression returns 6. x becomes 7.
       3. x++ : Post-increment. Expression returns 7. x becomes 8.

       The final expression evaluated is the third one, which returned 7.
       x finishes at 8.
    */
    y = (++x, x++, x++);
    printf("%d %d\n", x, y);                    // Outputs: 8 7
}

// ==========================================
// 5. Practical Application: Code Compression
// ==========================================
void avg(int val) {
    printf("Averaging: %d\n", val);
}

void execute_compression() {
    int a, b, sum;

    /*
       Instead of scattering variable assignments across 35 lines of code,
       the comma operator allows you to compress sequential setup logic directly
       into a function argument.

       traces the evaluation:
       1. a = 10 (returns 10)
       2. b = 5 (returns 5)
       3. sum = a + b (returns 15)

       The final value passed to avg() is 15.
    */
    avg( (a = 10, b = 5, sum = a + b) );
}
```

## All keywords in C program

- 32 standard keywords in the C language, structurally grouping them by their architectural role.

- Here is exactly how the board categorizes them:
  - **Datatypes (9):** `int`, `float`, `char`, `double`, `short`, `long`, `signed`, `unsigned`, `void`.

  - **Flow Control (12):** `if`, `else`, `while`, `for`, `do`, `switch`, `default`, `case`, `break`, `continue`, `goto`, `return`.

  - **Storage class Specifiers (5):** `auto`, `static`, `extern`, `register`.

  - **UDDT (User-Defined Data Types) (3):** `struct`, `union`, `enum`.

  - **Type Qualifiers (2):** `const`, `volatile`.

  - **Misc (1):** `sizeof(x)`, `typedef`.
