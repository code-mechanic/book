## Bitwise 1's Complement

```c
// Negative Binary Math
#include <stdio.h>

void main() {
    int a;

    // The bitwise NOT operator (~) flips every single bit in the register.
    a = ~0;

    // Because 'a' is a signed integer, the all-1s binary pattern is interpreted
    // as -1 by the hardware.
    printf("%d", a);                            // Output: -1
}

/*
   FLOW DIAGRAM (The Binary Transformation)

   Assume a 16-bit integer for this visual demonstration.

   Step 1: The '0' in binary
   ~    0000 0000 0000 0000

   Step 2: Applying the 1's Complement (~)
   Every '0' becomes a '1'.
      [ 1111 1111 1111 1111 ] => -1
*/
```

### The 2's Complement Shortcut (binary to decimal)

```c
/*
   Mathematical trick for quickly calculating its negative decimal value without
   doing a full 2's complement conversion (invert and add 1).

   Binary: 1111 1111 1111 0101 => -11

   The Math Trick:
   If all 1s (1111...1111) equals -1, you can just subtract the decimal values
   of the missing '0' bits.

   In the sequence ...0101, there are zeros at bit position 1 and bit position 3.
   - Bit position 3 has a decimal weight of 8.
   - Bit position 1 has a decimal weight of 2.

     -1  (The baseline if all bits were 1)
     -8  (Missing bit 3)
     -2  (Missing bit 1)
    ----
    -11
*/

```

The whiteboard uses a standard signed `int` for its bitwise operations. While this is
fine for a classroom math demonstration, **MISRA C strict guidelines universally prohibit performing bitwise operations on signed integers.**

When you apply bitwise shifts (`<<` or `>>`) to signed variables, the compiler's behavior is
heavily dependent on the architecture (like your STM32 ARM Cortex vs. your TI C2000). For
example, right-shifting a negative signed integer often causes "sign extension" (the CPU fills
the new leftmost bits with `1`s instead of `0`s to preserve the negative sign), which will
instantly corrupt a hardware peripheral register mask.

This is why hardware abstraction layers exclusively use `uint8_t`, `uint16_t`, and `uint32_t`
from `<stdint.h>`.

### The 2's Complement Shortcut (decimal to binary)

- Method: -N = ~(N - 1)

```c

/*
   -6 = ~(6 - 1)
      = ~(5)
      = ~(0000 0000 0000 0101)
      = 1111 1111 1111 1010
*/

```

- Method: Right-to-Left First '1' Shortcut

```c
/*

Here is how to calculate -6 in 16-bit binary.

1. Write positive 6 in 16-bit binary.
   6 = 0000 0000 0000 0110

2. Scan right-to-left and keep bits up to the first 1.
   The two rightmost bits are 10. Copy them exactly: ____ ____ ____ __10

3. Invert all remaining bits to the left.
   The remaining left bits are 0000 0000 0000 01.
   Invert them to: 1111 1111 1111 10.

4. Final 2's Complement Result:
   -6 = 1111 1111 1111 1010
*/
```

### The Actual Procedure: 2's Complement Decoding

```c
/*
   The whiteboard defines the universal hardware rules for interpreting
   signed binary numbers based on the Most Significant Bit (MSB).
*/

// ==========================================
// Rule 1: Positive Numbers
// ==========================================
/*
   "-> if MSB is 0
       number is +ve and it is Original data"

   If the leftmost bit (MSB) is 0, the hardware reads the remaining bits exactly
   as they are to calculate the positive decimal value.
*/

// ==========================================
// Rule 2: Negative Numbers & The 2's Complement
// ==========================================
/*
   "-> if MSB is 1
       number is -ve and result is it's 2's Complement"

   If the leftmost bit is 1, the CPU knows the number is negative.
   To find its actual magnitude (absolute value), the hardware must physically
   execute the 2's Complement procedure.
*/

/*
   FLOW DIAGRAM (The 2's Complement Calculation)

   The board demonstrates calculating the magnitude of the binary sequence
   from the previous board's shortcut: 1111 1111 1111 0101.

   MSB
   +-+
   |1| 111 1111 1111 0101   => -11
   +-+
    |
    | (Step 1: 1's Complement - Invert every single bit)
    v
    0  000 0000 0000 1010
                        1   (Step 2: Add 1 to the LSB)
  -----------------------
    0 000000 0000 1011      (Step 3: The Sum)

   The resulting binary (1011) equals 11 in decimal.
   Since the original MSB was 1, we attach the negative sign: -11.
*/
```

### Bitwise 1's Complement Math Shortcut

- Mathematical Formula: `~N = -(N + 1)`

```c

/*
   FLOW DIAGRAM (Binary Inversion & Subtraction Trick)

   Example 1: ~5
   ~ 0000 0000 0000 0101   (Decimal 5)
     1111 1111 1111 1010

     Shortcut Math:
     -1 (Base value if all bits were 1)
     -4 (Missing bit weight 4)
     -1 (Missing bit weight 1)
    ----
     -6

   Example 2: ~9
   ~ 0000 0000 0000 1001   (Decimal 9)
     1111 1111 1111 0110

     Shortcut Math:
     -1
     -8 (Missing bit weight 8)
     -1 (Missing bit weight 1)
    ----
    -10
*/

// ==========================================
// The Universal 1's Complement Formula
// ==========================================
/*
   A universal mathematical shortcut for
   applying the bitwise NOT (~) to any signed integer:

   1. Add 1
   2. Change sign

   Mathematical Formula: ~N = -(N + 1)
*/

void main() {
    // ~0  => -1     (0 + 1 = 1, change sign -> -1)
    // ~5  => -6
    // ~9  => -10
    // ~37 => -38

    // Applying the shortcut to large and negative numbers:
    // ~-6    => +5     (-6 + 1 = -5, change sign -> +5)
    // ~-3107 => +3106
    // ~10906 => -10907
}

```

### Logical NOT (!) vs. Bitwise NOT (~)

```c
#include <stdio.h>

void main() {
    // ==========================================
    // The Floating-Point Trap
    // ==========================================
    /*
       The board starts by debunking a common mathematical assumption:
       ~3.75 => -4.75 X  (Marked as incorrect)

       Instead, it results in a C.E (Compile Error).
       Bitwise operators manipulate raw binary at the hardware level. Because
       floating-point numbers (like 3.75) are stored in complex IEEE 754 format
       (sign bit, exponent, mantissa), flipping their bits does not yield a
       mathematically logical result. Therefore, the C compiler outright forbids it.
    */

    // ==========================================
    // Logical NOT (!)
    // ==========================================
    /*
       Logical NOT evaluates truthiness. Any non-zero value is 'true' (1),
       and 0 is 'false' (0).
       "Result is 1 or 0"
       "Applicable on any type of [data]"
    */
    printf("%d", !10);      // !10 => 0
    printf("%d", !100);     // !100 => 0
    printf("%d", !0);       // !0 => 1
    printf("%d", !-7);      // !-7 => 0
    printf("%d", !3.75);    // !3.75 => 0 (Valid because floats can be evaluated for truthiness)

    // ==========================================
    // Bitwise NOT (~)
    // ==========================================
    /*
       Bitwise NOT performs hardware-level binary inversion.
       "Result is an int."
       "Applicable on integral type data."
    */
    printf("%d", ~10);      // ~10 => -11 (Follows the ~N = -(N+1) rule from the previous board)
    printf("%d", ~100);     // ~100 => -101
    printf("%d", ~-7);      // ~-7 => 6

    float f = ~3.75;        // ~3.75 -> C.E (Compile Error)
}
```

## Left shift operator (<<) and Math shortcut

- Mathematical Formula: `a << b  =>  a * 2^b`

```c
#include <stdio.h>

void main() {
    /*
       Rule 1: Every bit shifts left by the specified number of positions.
       Rule 2: The Most Significant Bits (MSBs) that fall off the left edge are permanently
               discarded.
       Rule 3: The empty spaces created on the right edge are always padded with 0s.
    */

    // ==========================================
    // The Mathematical Shortcut
    // ==========================================
    /*
       A universal formula that bypasses
       binary conversions entirely:

       a << b  =>  a * 2^b
    */

    // ==========================================
    // Examples
    // ==========================================

    // Example 1: Positive Integer (Shift by 1)
    //
    // Hardware:   0000 0000 0000 0101 shifts left to
    //           0 0000 0000 0000 1010 (Decimal 10)
    //           ^                   ^
    //     (0 discarded)         (0 padded)
    //
    // Shortcut: 5 * 2^1 = 10
    int ex1 = 5 << 1;

    // Example 2: Positive Integer (Shift by 2)
    //
    // Hardware:   0000 0000 0000 0101 shifts left by two to
    //          00 0000 0000 0001 0100 (Decimal 20)
    //          ^^                  ^^
    //     (0 discarded)         (0 padded)
    //
    // Shortcut: 5 * 2^2 = 20
    int ex2 = 5 << 2;

    // Example 3: Negative Integer (Shift by 1)
    //
    // Hardware: The 2's complement binary of -5 (1111 1111 1111 1011).
    //           refer section "The 2's Complement Shortcut (decimal to binary)"
    //           to understand the convertion
    //
    //            1111 1111 1111 1011 shifts left by one to
    //          1 1111 1111 1111 0110 (decimal -10)
    //          ^                   ^
    //     (1 discarded)         (0 padded)
    //
    // Shortcut: -5 * 2^1 = -10
    int ex3 = -5 << 1;

    // Example 4: Negative Integer (Shift by 2)
    //
    // Hardware: The 2's complement binary of -6 (1111 1111 1111 1010).
    //           refer section "The 2's Complement Shortcut (decimal to binary)"
    //           to understand the convertion
    //
    //             1111 1111 1111 1010 shifts left by two to
    //          11 1111 1111 1110 1000 (decimal -24)
    //          ^^                  ^^
    //     (1 discarded)         (0 padded)
    //
    // Shortcut: -6 * 2^2 = -24
    int ex4 = -6 << 2;
}
```

## Right shift operator (>>) and Math shortcut

- Mathematical Formula:
  - For signed numbers:
    - If `a` is positive then `a >> b  =>  a / 2^b` (Gaps filled with 0)
    - if `a` is negative then `a >> b  => ~(~a / 2^b)` (Gaps filled with 1)
  - For unsigned number: `a >> b  =>  a / 2^b` (Gaps filled with 0)

```c
// Right Shift (>>) Mechanics, Sign Extension, and Shortcuts

#include <stdio.h>
#include <stdint.h>

void main() {
    // ==========================================
    // 1. Physical Hardware Mechanics & Gap Filling Rules
    // ==========================================
    /*
       When shifting bits to the right, the Least Significant Bits (LSBs)
       fall off the edge and are destroyed. However, this creates an
       empty gap on the left side of the register that must be filled.

       The hardware gap-filling rules:
       (1)"Signed data Gap is filled MSB". (Sign Extension)
       (2)"Unsigned data Gap is filled 0".
    */

    // ==========================================
    // 2. Positive Signed Integers
    // ==========================================
    /*
       Because the MSB of a positive number is 0, the gap is filled with 0s.
       Shortcut Formula: a >> b  =>  a / 2^b  (Integer Division)

       Example 1: 5 >> 1
       Binary:   0000 0000 0000 0101
       Shifted:  0000 0000 0000 0010 1(The '1' drops off)
       Shortcut: 5 / 2^1 = 2

       Example 2: 11 >> 2
       Binary:   0000 0000 0000 1011
       Shifted:  0000 0000 0000 0010 11(The '11' drops off)
       Shortcut: 11 / 2^2 = 2
    */
    int ex1 = 5 >> 1;
    int ex2 = 11 >> 2;

    // ==========================================
    // 3. Negative Signed Integers
    // ==========================================
    /*
       Because the MSB of a negative number is 1, the gap is forcefully filled
       with 1s to preserve the negative sign (Sign Extension).
       Shortcut Formula: ~(~a / 2^b)

       Example 3: -9 >> 1
       Binary:   1111 1111 1111 0111
       Shifted:  1111 1111 1111 1011 1(Fills left with '1')
       Shortcut: ~(~(-9) / 2^1) => ~(~(~8) / 2) => ~(8 / 2) => ~4 => -5
                 refer section "The 2's Complement Shortcut (decimal to binary)"
                 to understand how -9 is converted to ~8

       Example 4: -6 >> 2
       Binary:   1111 1111 1111 1010
       Shifted:  1111 1111 1111 1110 10(Fills left with '1')
       Shortcut: ~(~(-6) / 2^2) => ~(5 / 4) => ~1 => -2
    */
    int ex3 = -9 >> 1;
    int ex4 = -6 >> 2;

    // ==========================================
    // 4. Unsigned Data (Hexadecimal)
    // ==========================================
    /*
       When the 'U' suffix is applied, the compiler treats the data as unsigned,
       meaning the left gap is ALWAYS filled with 0s, regardless of the MSB.

       Example: 0xA935U >> 2
       Binary:  1010 1001 0011 0101
       Shifted: 0010 1010 0100 1101 (The leftmost bits become 00)
       Hex:     2    A    4    d    => 0x2A4DU
    */
    uint16_t hex_shift = 0xA935U >> 2;

    // ==========================================
    // 5. Machine Dependent Undefined Behavior
    // ==========================================
    /*
       Two specific shifting scenarios as "Machine dependent"
       (Undefined Behavior) when compiled with GCC on a 32-bit architecture:

       (1)Shifting by a value greater than or equal to the register width:
          10 << 40  (A 32-bit register physically cannot shift 40 times)
          81 >> 100

       (2)Shifting by a negative position:
          10 << -2  (Hardware does not know how to shift in reverse)
          8 >> -3
    */
}

```

## Truth Tables and Bitwise vs. Logical AND

```c
#include <stdio.h>

void main() {
    // ==========================================
    // 1. Bitwise Logic Truth Table
    // ==========================================
    /*
       The whiteboard establishes the fundamental logic gate behavior for
       the three primary bitwise operators acting on two bits (b1, b2):

       | b1 | b2 | b1 & b2 (AND) | b1 ^ b2 (XOR) | b1 | b2 (OR) |
       |----|----|---------------|---------------|--------------|
       |  0 |  0 |       0       |       0       |       0      |
       |  0 |  1 |       0       |       1       |       1      |
       |  1 |  0 |       0       |       1       |       1      |
       |  1 |  1 |       1       |       0       |       1      |

       - AND (&): Only outputs 1 if BOTH bits are 1.
       - XOR (^): Only outputs 1 if the bits are DIFFERENT.
       - OR (|): Outputs 1 if AT LEAST ONE bit is 1.
    */

    // ==========================================
    // 2. Bitwise AND (&) vs. Logical AND (&&)
    // ==========================================
    /*
       The board then contrasts hardware-level bitwise masking against
       C's boolean truthiness evaluation using positive and negative integers.
    */

    // Example 1: 8 and 10
    /*
       Bitwise: 8 & 10
        8:  0000 0000 0000 1000
       10:  0000 0000 0000 1010
       ------------------------
        &:  0000 0000 0000 1000  => 8

       Logical: 8 && 10
       Because both 8 and 10 are non-zero, they evaluate as 'true' (1).
       true && true => 1
    */
    int bitwise_pos = 8 & 10;    // Result: 8
    int logical_pos = 8 && 10;   // Result: 1

    // Example 2: -8 and 10
    /*
       Bitwise: -8 & 10
       The board shows the 2's complement derivation for -8 (inverting positive 8
       to 0111, then adding 1 to get 1000).

       -8:  1111 1111 1111 1000
       10:  0000 0000 0000 1010
       ------------------------
        &:  0000 0000 0000 1000  => 8

       Logical: -8 && 10
       Even though -8 is negative, it is non-zero, meaning it is 'true'.
       true && true => 1
    */
    int bitwise_neg = -8 & 10;   // Result: 8
    int logical_neg = -8 && 10;  // Result: 1
}
```

## Bitwise Algebra and Hardware Control Rules

```c

#include <stdint.h>

void main() {
    // ==========================================
    // 1. The Fundamental Bitwise Identities
    // ==========================================
    /*
       The top of the whiteboard defines algebraic rules for a single bit 'X'
       (which represents any unknown state, 0 or 1) when operated against a
       constant 1 or 0.

       AND (&) - The "Forcer to Zero"
       X & 1 => X   (Leaves the bit unchanged)
       X & 0 => 0   (Forces the bit to 0)

       XOR (^) - The "Inverter"
       X ^ 1 => ~X  (Flips the bit. The board marks this as X with a bar over it)
       X ^ 0 => X   (Leaves the bit unchanged)

       OR (|) - The "Forcer to One"
       X | 1 => 1   (Forces the bit to 1)
       X | 0 => X   (Leaves the bit unchanged)
    */

    // ==========================================
    // 2. The Three Golden Rules of Hardware Control
    // ==========================================
    /*
       These algebraic identities directly translate into the three universal
       commands used in embedded firmware, written on the bottom of the board:

       1. Set / Turn ON    => OR (|)
       2. Clear / Turn OFF => AND (&)
       3. Toggle           => XOR (^)
    */

    uint32_t PORTA = 0x00000000; // Simulated 32-bit hardware register

    // ------------------------------------------
    // Example: Turn ON bit 5 (Set)
    // ------------------------------------------
    // Using a mask of (1 << 5) puts a '1' at bit 5 and '0's everywhere else.
    // Because X | 0 = X, bits 0-4 and 6-31 are perfectly protected/unchanged.
    // Because X | 1 = 1, bit 5 is forced to 1.
    PORTA = PORTA | (1 << 5);

    // ------------------------------------------
    // Example: Turn OFF bit 5 (Clear)
    // ------------------------------------------
    // We use AND with an INVERTED mask: ~(1 << 5). This puts a '0' at bit 5 and '1's elsewhere.
    // Because X & 1 = X, bits 0-4 and 6-31 are perfectly protected/unchanged.
    // Because X & 0 = 0, bit 5 is forced to 0.
    PORTA = PORTA & ~(1 << 5);

    // ------------------------------------------
    // Example: Toggle bit 5
    // ------------------------------------------
    // Because X ^ 0 = X, all surrounding bits are protected/unchanged.
    // Because X ^ 1 = ~X, bit 5 instantly reverses its current state.
    PORTA = PORTA ^ (1 << 5);
}
```

- To set a bit, `data = data | (1 << bit_pos)`
- To clear a bit, `data = data & (~(1 << bit_pos))`
- To toggle a bit, `data = data ^ (1 << bit_pos)`

## Problem solving

### Check if the nth bit is set

```c
bool is_bit_set(uint32_t x, uint8_t n)
{
    return (x >> n) & 1U;
    /* OR: return (x & (1U << n)) != 0; */
}
```

### Set the nth bit

```c
uint32_t set_bit(uint32_t x, uint8_t n)
{
    return x | (1U << n);
}
```

### Clear the nth bit

```c
uint32_t clear_bit(uint32_t x, uint8_t n)
{
    return x & ~(1U << n);
}
```

### Toggle the nth bit

```c
uint32_t toggle_bit(uint32_t x, uint8_t n)
{
    return x ^ (1U << n);
}
```

### Count number of set bits

```c
uint8_t count_set_bits(uint32_t x)
{
    uint8_t count = 0;
    while (x) {             /* loop runs exactly as many times as there are set bits */
        x &= x - 1;        /* x-1 flips all bits from LSB up to (and including) the
                               lowest set bit, so AND-ing zeroes that bit out.
                               e.g.  x     = 1010 1000
                                     x-1   = 1010 0111
                                     x&x-1 = 1010 0000  <- one set bit gone */
        count++;
    }
    return count;           /* result = number of 1-bits in original x */
}
```

### Check if a number is a power of 2

```c
bool is_power_of_2(uint32_t n)
{
    /* n=0 excluded: 0 is not a power of 2 */
    return (n != 0) && ((n & (n - 1)) == 0);
}
```

### Swap two numbers using XOR

```c
void xor_swap(uint32_t *a, uint32_t *b)
{
    if (a != b) {          /* guard against aliasing */
        *a ^= *b;
        *b ^= *a;          /* *b = original *a */
        *a ^= *b;          /* *a = original *b */
    }
}
```

### Find first set bit in a number

```c
/* Shift right until LSB is 1, counting each step.
 * O(position of lowest set bit) — worst case O(32).               */
int first_set_bit_manual(uint32_t x)
{
    if (!x) return -1;

    int pos = 0;
    while ((x & 1U) == 0) {    /* while LSB is 0... */
        x >>= 1;                /* ...shift right (discard LSB) */
        pos++;                  /* ...and count the step */
    }
    return pos;                 /* pos where (x >> pos) & 1 is first true */
}

/* isolation trick
 *
 * -x in two's complement = ~x + 1
 * ~x flips all bits, +1 then ripples carry rightward until it sets
 * exactly the position of the original lowest set bit.
 * Result is a VALUE with only that one bit set, not the position.
 *
 * e.g.  x      = 0000 1010 0  (LSB at bit 1)
 *       -x     = 1111 0110 0
 *       x & -x = 0000 0010 0  <-> isolated LSB as a value           */
uint32_t isolate_lsb(uint32_t x)
{
    return x & (-x);            /* returns the bit VALUE, not position */
}
```

> x = 0000 1010 1000 (lowest set bit at position 3)
> x - 1 = 0000 1010 0111 (borrow flips bits 0..3)
> x & -x = 0000 0000 1000 (isolates ONLY bit 3 as a value)

### Find last set bit in a number

```c
/* Keep shifting x right until it becomes 0.
 * Each shift discards one bit from the top.
 * The number of shifts needed = position of the highest set bit.
 *
 * e.g.  x = 0110 0100  (decimal 100)
 *       shift 1 -> 0011 0010   pos = 1
 *       shift 2 -> 0001 1001   pos = 2
 *       ...
 *       shift 6 -> 0000 0001   pos = 6
 *       shift 7 -> 0000 0000   loop exits, return pos = 6            */
int last_set_bit_shift(uint32_t x)
{
    if (!x) return -1;

    int pos = 0;
    while(x) {
        x = x >> 1     /* shift right; loop exits when x becomes 0 */
        pos++;         /* count each shift, final value = MSB position */
    }
    return pos;
}

/* Binary search / divide-and-conquer
 *
 * Narrows down the MSB position in exactly 5 steps (log2 of 32).
 * Checks whether any bit exists in the upper half; if yes, shift
 * the entire value down by that half and accumulate the offset.
 * O(log 32) = O(5) — no loop dependency on the actual bit position.
 *
 * Step sizes:  16 -> 8 -> 4 -> 2 -> 1                                  */
int last_set_bit_bsearch(uint32_t x)
{
    if (!x) return -1;

    int pos = 0;

    if (x & 0xFFFF0000U) { pos += 16; x >>= 16; }  /* bit in upper 16? */
    if (x & 0x0000FF00U) { pos +=  8; x >>=  8; }  /* bit in upper 8?  */
    if (x & 0x000000F0U) { pos +=  4; x >>=  4; }  /* bit in upper 4?  */
    if (x & 0x0000000CU) { pos +=  2; x >>=  2; }  /* bit in upper 2?  */
    if (x & 0x00000002U) { pos +=  1; x >>=  1; }  /* bit in upper 1?  */

    return pos;
}
```

### Reverse bits of 32-bit number

```c
/*
 * Reverse all 32 bits of an unsigned integer.
 * e.g.  0b 1011 0100 0000 0000 0000 0000 0000 0001
 *       0b 1000 0000 0000 0000 0000 0000 0010 1101 (result)
 */

/* Divide-and-conquer with bitmasks (portable, O(log 32))
 *
 * Core idea: repeatedly swap the two halves of the number,
 * each time at half the previous granularity.
 *
 * 5 stages: 16-bit halves -> bytes -> nibbles -> bit-pairs -> bits
 *
 * Mask anatomy (memorise these — they come up in other problems too):
 *
 *   0xFFFF0000 = 1111 1111 1111 1111 | 0000 0000 0000 0000  (upper half)
 *   0x0000FFFF = 0000 0000 0000 0000 | 1111 1111 1111 1111  (lower half)
 *
 *   0xFF00FF00 = 1111 1111 | 0000 0000 | 1111 1111 | 0000 0000  (odd bytes)
 *   0x00FF00FF = 0000 0000 | 1111 1111 | 0000 0000 | 1111 1111  (even bytes)
 *
 *   0xF0F0F0F0 = 1111 | 0000 | 1111 | 0000 | ...  (odd nibbles)
 *   0x0F0F0F0F = 0000 | 1111 | 0000 | 1111 | ...  (even nibbles)
 *
 *   0xCCCCCCCC = 11 | 00 | 11 | 00 | ...           (odd bit-pairs)
 *   0x33333333 = 00 | 11 | 00 | 11 | ...           (even bit-pairs)
 *
 *   0xAAAAAAAA = 1010 1010 ...                      (odd single bits)
 *   0x55555555 = 0101 0101 ...                      (even single bits)
 *
 * Pattern: each stage's two masks are bitwise complements of each other.
 * Each stage shifts by exactly half its working block size.          */

uint32_t reverse32(uint32_t x)
{
    /* Stage 1: swap upper 16 bits with lower 16 bits
     *   before: [A B C D | E F G H | I J K L | M N O P]
     *   after:  [I J K L | M N O P | A B C D | E F G H]  */
    x = ((x & 0xFFFF0000U) >> 16) |
        ((x & 0x0000FFFFU) << 16);

    /* Stage 2: swap odd bytes with even bytes within each 16-bit half
     *   before: [I J K L | M N O P | A B C D | E F G H]
     *   after:  [M N O P | I J K L | E F G H | A B C D]  */
    x = ((x & 0xFF00FF00U) >>  8) |
        ((x & 0x00FF00FFU) <<  8);

    /* Stage 3: swap odd nibbles with even nibbles within each byte
     *   each byte: [HI LO] -> [LO HI]                      */
    x = ((x & 0xF0F0F0F0U) >>  4) |
        ((x & 0x0F0F0F0FU) <<  4);

    /* Stage 4: swap odd bit-pairs with even bit-pairs within each nibble
     *   each nibble: [b3 b2 | b1 b0] -> [b1 b0 | b3 b2]   */
    x = ((x & 0xCCCCCCCCU) >>  2) |
        ((x & 0x33333333U) <<  2);

    /* Stage 5: swap every odd bit with its even neighbour
     *   final swap of adjacent bits — completes the full reversal  */
    x = ((x & 0xAAAAAAAAU) >>  1) |
        ((x & 0x55555555U) <<  1);

    return x;
}

/* Naive loop
 *
 * Extract LSB of x each iteration, push it into result from the MSB end.
 * O(32) — always 32 iterations regardless of bit pattern.           */
uint32_t reverse32_loop(uint32_t x)
{
    uint32_t result = 0;
    int bits = 32;

    while (bits--) {
        result = result << 1;        /* shift result up*/
        result = result | (x & 1U);  /* OR in LSB of x */
        x = x >> 1;                  /* discard the LSB just consumed */
    }

    return result;
}
```

### Swap bytes / Endianess conversion

```c
// C99 Portable Auto-Detecting Byte Swap with Visual Data Flow

#include <stdio.h>
#include <stdint.h>
#include <limits.h>

// ==========================================
// VISUAL 1: The 16-bit Swap Mechanics
// ==========================================
/*
   Original Data: 0x1A2B
   Memory Layout: [ Byte 1 ] [ Byte 0 ]
                  [   1A   ] [   2B   ]

   Step 1: Masking & Shifting Byte 0 (0x2B)
   (x & 0x00FFU)  => [ 00 ] [ 2B ]
         << 8     => [ 2B ] [ 00 ]  <-- Shifted Left 8 bits

   Step 2: Masking & Shifting Byte 1 (0x1A)
   (x & 0xFF00U)  => [ 1A ] [ 00 ]
         >> 8     => [ 00 ] [ 1A ]  <-- Shifted Right 8 bits

   Step 3: Bitwise OR (|)
     [ 2B ] [ 00 ]
   | [ 00 ] [ 1A ]
   ---------------
     [ 2B ] [ 1A ]  => 0x2B1A (Swapped!)
*/
#define SWAP_16_MACRO(x) (uint16_t)( \
    (((uint16_t)(x) & 0x00FFU) << 8) | \
    (((uint16_t)(x) & 0xFF00U) >> 8)   \
)

// ==========================================
// VISUAL 2: The 32-bit Swap Mechanics
// ==========================================
/*
   Original Data: 0x11223344
   Memory Layout: [ Byte 3 ] [ Byte 2 ] [ Byte 1 ] [ Byte 0 ]
                  [   11   ] [   22   ] [   33   ] [   44   ]

   Movement Flow:
   [ 11 ] -----------------------> moves right by 24 (>> 24)
          [ 22 ] ----------------> moves right by 8  (>> 8)
                 [ 33 ] ---------> moves left by 8   (<< 8)
                        [ 44 ] --> moves left by 24  (<< 24)

   Masking & Shifting Breakdown:
   (x & 0x000000FFUL) << 24 => [ 44 ] [ 00 ] [ 00 ] [ 00 ]
   (x & 0x0000FF00UL) << 8  => [ 00 ] [ 33 ] [ 00 ] [ 00 ]
   (x & 0x00FF0000UL) >> 8  => [ 00 ] [ 00 ] [ 22 ] [ 00 ]
   (x & 0xFF000000UL) >> 24 => [ 00 ] [ 00 ] [ 00 ] [ 11 ]
   -------------------------------------------------------
   Bitwise OR (|) Fusion    => [ 44 ] [ 33 ] [ 22 ] [ 11 ]
*/
#define SWAP_32_MACRO(x) (uint32_t)( \
    (((uint32_t)(x) & 0x000000FFUL) << 24) | \
    (((uint32_t)(x) & 0x0000FF00UL) <<  8) | \
    (((uint32_t)(x) & 0x00FF0000UL) >>  8) | \
    (((uint32_t)(x) & 0xFF000000UL) >> 24)   \
)

// ==========================================
// 64-Bit Swap (Same visual logic applied across 8 bytes)
// ==========================================
#define SWAP_64_MACRO(x) (uint64_t)( \
    (((uint64_t)(x) & 0x00000000000000FFULL) << 56) | \
    (((uint64_t)(x) & 0x000000000000FF00ULL) << 40) | \
    (((uint64_t)(x) & 0x0000000000FF0000ULL) << 24) | \
    (((uint64_t)(x) & 0x00000000FF000000ULL) <<  8) | \
    (((uint64_t)(x) & 0x000000FF00000000ULL) >>  8) | \
    (((uint64_t)(x) & 0x0000FF0000000000ULL) >> 24) | \
    (((uint64_t)(x) & 0x00FF000000000000ULL) >> 40) | \
    (((uint64_t)(x) & 0xFF00000000000000ULL) >> 56)   \
)

// ==========================================
// Auto-Routing C99 Macro
// ==========================================
#define BYTESWAP(var) ( \
    ((sizeof(var) * CHAR_BIT) == 64) ? SWAP_64_MACRO(var) : \
    ((sizeof(var) * CHAR_BIT) == 32) ? SWAP_32_MACRO(var) : \
    ((sizeof(var) * CHAR_BIT) == 16) ? SWAP_16_MACRO(var) : \
    (var) \
)

void main() {
    uint16_t raw_16 = 0x1A2B;
    uint32_t raw_32 = 0x11223344;

    uint16_t fixed_16 = BYTESWAP(raw_16);
    uint32_t fixed_32 = BYTESWAP(raw_32);

    printf("16-bit: Raw: %04X | Swapped: %04X\n", raw_16, fixed_16);
    printf("32-bit: Raw: %08X | Swapped: %08X\n", raw_32, fixed_32);
}
```

### Clear all the bits from MSB to nth bit pos

```c
/*
 * Clear all bits from the MSB down to position n (inclusive).
 * Keep bits [n-1 .. 0] untouched.
 *
 * Visual:
 *   bit pos:  31 30 29 ... n+1  n  | n-1  n-2 ... 1   0
 *   before:    ?  ?  ? ...  ?   ?  |  ?    ?  ... ?   ?
 *   after:     0  0  0 ...  0   0  |  ?    ?  ... ?   ?   <- upper cleared
 *                                    ^^^^^^^^^^^^^^^^^^^
 *                                    these bits preserved exactly
 *
 * e.g.  x = 0xFF  (1111 1111),  n = 4
 *       clear bits [7..4], keep bits [3..0]
 *       result = 0x0F  (0000 1111)
 */

/*  Method 1: Lower-bits mask (preferred — one expression)
 *
 * Key insight: (1U << n) - 1  produces exactly n ones in the low positions.
 *
 *   n = 4:
 *   1U << 4         = 0000 0000 0001 0000   (1 at position n)
 *   (1U << 4) - 1   = 0000 0000 0000 1111   (all ones below position n)
 *
 * AND-ing with this mask:
 *   — bits [n-1..0] : masked with 1 -> preserved unchanged
 *   — bits [31..n]  : masked with 0 -> forced to 0 (cleared)            */

uint32_t clear_msb_to_n(uint32_t x, uint8_t n)
{
    return x & ((1U << n) - 1U);    /* keep only the lower n bits */
    /*
     * (1U << n) - 1U  builds the "keep" mask at compile time if n is
     * a constant — zero runtime cost on any architecture.
     */
}

/*  Method 2: Complement + shift (shows understanding of bit width)
 *
 * Build a mask of ones for the upper bits, then invert and AND.
 *
 *   ~0U             = 1111 1111 1111 1111 1111 1111 1111 1111
 *   ~0U << n        = 1111 1111 1111 1111 1111 1111 1111 0000  (n=4)
 *   ~(~0U << n)     = 0000 0000 0000 0000 0000 0000 0000 1111  <- same mask
 *
 * Identical result to Method 1, but makes the complement relationship
 * explicit — useful when explaining to an interviewer.                  */

uint32_t clear_msb_to_n_v2(uint32_t x, uint8_t n)
{
    return x & ~(~0U << n);         /* ~0U = all ones; shift left clears low n;
                                       invert again -> low n ones = keep mask  */
}
```

### Check if the number is positive or negative

```c
// Portable Bitwise MSB Check (8, 16, 32, and 64-bit agnostic)

#include <stdio.h>
#include <stdint.h>
#include <limits.h> // Required for CHAR_BIT

// ==========================================
// 1. The Portable Macro
// ==========================================
/*
   Instead of hardcoding '31', we dynamically calculate the exact position
   of the Most Significant Bit (MSB) using the compiler's memory mapping.

   - sizeof(var) returns the physical memory footprint in bytes.
   - CHAR_BIT (from limits.h) converts those bytes into hardware bits.
   - We subtract 1 to get the correct 0-indexed left shift amount.
   - We use '1ULL' (Unsigned Long Long) to guarantee the mask is always at least
     64 bits wide. This prevents Undefined Behavior when shifting up to 63 times.
*/
#define IS_NEGATIVE(var) ((var) & (1ULL << ((sizeof(var) * CHAR_BIT) - 1)))

void main() {
    // ==========================================
    // 2. Defining Multi-Sized Test Subjects
    // ==========================================
    int8_t  num_8bit  = -42;          // 8-bit (MSB is bit 7)
    int16_t num_16bit = 32000;        // 16-bit (MSB is bit 15)
    int32_t num_32bit = -2000000;     // 32-bit (MSB is bit 31)
    int64_t num_64bit = 9000000000;   // 64-bit (MSB is bit 63)

    // ==========================================
    // 3. Executing the Portable Checks
    // ==========================================

    // Shifts 1ULL left by (1 * 8) - 1 = 7
    if (IS_NEGATIVE(num_8bit)) {
        printf("8-bit: Negative\n");
    } else {
        printf("8-bit: Positive\n");
    }

    // Shifts 1ULL left by (2 * 8) - 1 = 15
    if (IS_NEGATIVE(num_16bit)) {
        printf("16-bit: Negative\n");
    } else {
        printf("16-bit: Positive\n");
    }

    // Shifts 1ULL left by (4 * 8) - 1 = 31
    if (IS_NEGATIVE(num_32bit)) {
        printf("32-bit: Negative\n");
    } else {
        printf("32-bit: Positive\n");
    }

    // Shifts 1ULL left by (8 * 8) - 1 = 63
    if (IS_NEGATIVE(num_64bit)) {
        printf("64-bit: Negative\n");
    } else {
        printf("64-bit: Positive\n");
    }
}
```

### Bitwise Optimizations for Multiplication, Division, and Modulo for power of 2 number

```c

#include <stdint.h>

void main() {
    uint32_t x = 50;
    uint32_t result;

    // ==========================================
    // 1. Direct Power-of-2 Replacements
    // ==========================================
    /*
       By bypassing the Arithmetic Logic Unit's (ALU) standard multiplier,
       you can route the operation directly through the hardware barrel shifter.
    */
    result = x * 8;      // Standard Multiplication
    result = x << 3;     // Optimized: 8 is 2^3, so shift left by 3

    result = x / 4;      // Standard Division
    result = x >> 2;     // Optimized: 4 is 2^2, so shift right by 2

    // ==========================================
    // 2. Non-Power-of-2 Multiplication (Shift-and-Add)
    // ==========================================
    /*
       To multiply by a number that is not a power of 2 (like 10), you can
       break the multiplier down into its binary power-of-2 components.
       10 in binary is 8 + 2 (which are 2^3 and 2^1).

       Math Breakdown:
       x * 10 = x * (8 + 2) = (x * 8) + (x * 2)
    */
    result = x * 10;                     // Standard Multiplication
    result = (x << 3) + (x << 1);        // Optimized: Shift-and-Add

    // ==========================================
    // 3. Modulo (Remainder) Optimization
    // ==========================================
    /*
       The modulo operator (%) uses division under the hood. If you need the
       remainder of a division by a power of 2, you can replace the division
       entirely with a Bitwise AND (&).

       Mask Formula: (Divisor - 1)
       Example: Modulo 8. The mask is 8 - 1 = 7 (Binary 0000 0111).
       This mathematically forces all higher multiples of 8 to zero, leaving
       only the remainder in the lower 3 bits.
    */
    result = x % 8;      // Standard Modulo
    result = x & 7;      // Optimized: Bitwise Masking
}
```
