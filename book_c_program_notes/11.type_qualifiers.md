## Const

- The const Keyword and Variable Mutability

```c
#include <stdio.h>

// ==========================================
// 1. Valid Constant Initialization
// ==========================================
void const_initialization() {
    int a = 500;
    /*
    1. const variables are only able to initialize during variable declaration.
    RHS might be constant or a variable.

    2. A constant variable should be initialized at the time of its declaration.
    */
   const int i = 10;
   const int j = a;

    // Output: 10 500
    printf("%d %d\n", i, j);

    // Modifying the variable will not change the const i variable
    a = 600;

    // Output: 10 500
    printf("%d %d", i, j);
}

// ==========================================
// 2. Modifying a Constant (Compile Error)
// ==========================================
void const_modification_error() {
    const int i = 100;

    /*
       Attempting to alter the value of a constant variable results in a compilation error.
       A const object cannot be modified after it has been initialized.
    */
    printf("%d", ++i);                   // X Error: const object cannot modify
}

// ==========================================
// 3. Deferred Assignment (Compile Error)
// ==========================================
void const_deferred_assignment() {
    const int i;                            // Variable declared without initialization

    /*
       Because the variable is declared as const, it becomes read-only immediately upon creation.
       Assigning a value to it on a subsequent line violates this constraint.
    */
    i = 10;                              // X Error
    printf("%d", i);
}

// ==========================================
// 4. Uninitialized Constant Behavior
// ==========================================
void const_uninitialized() {
    const int i;

    /*
       If a local const integer is declared without an initial value and then accessed,
       it simply evaluates to whatever residual memory data is at that address.
    */
    printf("%d", i);                        // Output: G.V (Garbage Value)
}

```

### Real time scenario to use const keyword

```c
#include <stdio.h>

// ==========================================
// Const in Function Arguments
// ==========================================
/*
   Applying the 'const' qualifier to function parameters prevents the function
   from accidentally modifying the values passed to it.
   This is a fundamental practice in defensive programming. It guarantees that
   the function treats the inputs strictly as read-only data within its scope.
*/
void sum(const int a, const int b) {
    // The variables 'a' and 'b' can be read and used in expressions.
    printf("%d", a + b);

    /*
       Attempting to modify the parameters would result in a compilation error:
    */
   a = a + 1; // X Compile Error: assignment of read-only parameter 'a'
}

void main_function_parameters() {
    // These variables are entirely mutable in the caller's scope.
    int x = 10, y = 5;

    /*
       It is perfectly valid to pass non-const variables into const parameters.
       The compiler simply enforces that 'sum' cannot alter its local copies,
       regardless of how the original variables were declared in 'main'.
    */
    sum(x, y);
}
```

```c
void main()

    const int i = 10;

    // Some compiler generate warnings / error for implicit int
        const k = 30;

    NOTE: This redundancy is harmless on standard variables, but the placement

    const int const l = 40;
```

### Pointers and the const Keyword

```c
#include <stdio.h>

// ==========================================
// 1. Single Pointers and Const Placement
// ==========================================
void pointer_const_variations() {
    int a = 10, b = 20;

    // ------------------------------------------
    // Standard Pointer (Everything Modifiable)
    // ------------------------------------------
    int *p_standard = &a;
    *p_standard = 888;                      // (ok) value is changed
    p_standard = &b;                        // (ok) address is changed

    // ------------------------------------------
    // Pointer to Constant Integer
    // ------------------------------------------
    const int *p_to_const = &a;             // [P is pointer to const int]
    *p_to_const = 888;                      // X (X) Cannot change the value
    p_to_const = &b;                        // (ok) (Tick) Can change the address

    // ------------------------------------------
    // Constant Pointer to Integer
    // ------------------------------------------
    int *const const_p = &a;                // [P is constant pointer to integer]
    *const_p = 888;                         // (ok) (Tick) Can change the value
    const_p = &b;                           // X (X) Cannot change the address

    // ------------------------------------------
    // Constant Pointer to Constant Integer
    // ------------------------------------------
    const int *const const_p_to_const = &a; // [P is constant pointer to constant integer]
    *const_p_to_const = 888;                // X (X) Cannot change the value
    const_p_to_const = &b;                  // X (X) Cannot change the address
}

/*
for making data to be constant we can put const keyword before or after the data-type.
For example:
const int *p = &a; same as
int const *p = &a;

But for making pointer to be constant we should place const keyword appropriately.

*/
```

### Advanced Multiple Indirection (Double & Triple Pointers)

To determine which parts of a complex pointer chain are modifiable, read the
declaration from right to left, starting at the variable name `p`.

| Declaration                   | `p`  | `*p` | `**p` | `***p` | Right-to-Left Reading Breakdown                                                                                          |
| ----------------------------- | ---- | ---- | ----- | ------ | ------------------------------------------------------------------------------------------------------------------------ |
| `int **p;`                    | (ok) | (ok) | (ok)  | N/A    | `p` is a pointer to a pointer to an `int`. Everything is modifiable.                                                     |
| `int *const *p;`              | (ok) | X    | (ok)  | N/A    | `p` is a pointer (`p` (ok)) to a `const` pointer (`*p` X) to an `int` (`**p` (ok)).                                      |
| `int const **const p;`        | X    | (ok) | X     | N/A    | `p` is a `const` pointer (`p` X) to a pointer (`*p` (ok)) to a `const int` (`**p` X).                                    |
| `int *const *const *const p;` | X    | X    | X     | (ok)   | `p` is a `const` pointer (`p` X) to a `const` pointer (`*p` X) to a `const` pointer (`**p` X) to an `int` (`***p` (ok)). |

### Modification errors

```c
//------------------------------------------------------
// 1. Pointer to Constant Data (Data Modification Error)
//------------------------------------------------------
#include <stdio.h>

const int *func();

int main() {
    // 'ptr' is a pointer to a 'const int'.
    // The address it holds can be changed, but the data it points to is read-only.
    const int *ptr = func();

    // X COMPILE ERROR: Assignment of read-only location '*ptr'
    // Attempting to modify the underlying value violates the 'const int' qualification.
    *ptr = 222;

    printf("%d", *ptr);
    return 0;
}

const int *func() {
    int data = 50;
    int *x = &data;

    /*
       CRITICAL RUNTIME FLAW:
       While the compiler flags the const violation above, returning 'x' here
       returns the address of a local stack variable ('data'). Once 'func' exits,
       this memory is freed, leaving 'ptr' in main() as a dangling pointer.
    */
    return x;
}

//-------------------------------------------------
// 2. Constant Pointer (Pointer Modification Error)
//-------------------------------------------------
#include <stdio.h>

int * const func();

int main() {
    int b = 333;

    // 'ptr' is a 'const' pointer to a standard 'int'.
    // The data it points to can be modified, but the address it holds is read-only.
    int * const ptr = func();

    // (ok) VALID: The underlying integer data is mutable, so dereferencing and assigning works.
    *ptr = 222;

    // X COMPILE ERROR: Assignment of read-only variable 'ptr'
    // Attempting to assign a new address (&b) to 'ptr' violates the '* const' qualification.
    ptr = &b;

    printf("%d", *ptr);
    return 0;
}

int * const func() {
    int data = 50;
    int * const x = &data;

    // Note: This also suffers from the same dangling pointer logical error as the first example.
    return x;
}
```

### Const Limitations and Indirect Modification

```c
#include <stdio.h>

// ==========================================
// 1. Const Variables vs. Constant Expressions
// ==========================================
const int i = 10;

void const_expression_limitations(int x) {
    /*
       In C, a 'const' qualified variable is read-only, but it is NOT considered a true
       compile-time "constant expression" (unlike literal values or macro definitions).
       Because i is not accept as constant even const is applied, it cannot be used
       where the compiler strictly demands a resolved constant at compile time.
    */

    // 1. Switch Case Labels
    switch(x) {
        case i:                          // X Compile Error: Case label does not reduce to an integer constant.
            break;
    }

    // 2. Array Sizes (in strict/older C standards)
    int arr[i];                          // X Compile Error: Variable-length arrays notwithstanding, fixed arrays require constant expressions.
}

// ==========================================
// 2. Indirect Modification (Local vs. Global)
// ==========================================
/*
   Const data typed is not directly changable but indirectly they are changable.
   However, whether this indirect modification succeeds at runtime depends entirely
   on where the variable is allocated in memory.
*/

void local_const_modification() {
    // Local variables are allocated on the Stack, which is read/write memory.
    const int i = 10;

    // We create a standard pointer and point it to the address of the const variable.
    // (Note: Modern compilers will issue a warning here for discarding the const qualifier).
    int *p = (int *)&i;

    // Indirectly overriding the value.
    *p = 888;

    // Output: 888
    // The assignment succeeds, and the value is changed.
    printf("%d\n", i);
}

// Global const variables are usually allocated in the Read-Only Data segment (.rodata).
const int global_i = 10;

void global_const_modification() {
    int *p = (int *)&global_i;

    /*
       Attempting to write to a read-only memory segment triggers an OS-level hardware trap.
    */
    *p = 888;                            // X RUNTIME ERROR: Segmentation fault because of Global Read only.
}
```

## volatile

```c
// The volatile Type Qualifier (TQ) and Compiler Optimization

#include <stdio.h>

// ==========================================
// 1. The Threat of Code Optimization
// ==========================================
/*
   Compilers aggressively optimize code to minimize memory bottlenecks and speed up execution.
   Instead of fetching a variable from RAM every time it is used, the compiler may cache
   it inside a CPU Register (within the Processor/ALU) and perform operations locally.
*/

void standard_optimization() {
    int a = 1;                          // Variable 'a' is allocated in RAM

    /*
       The compiler analyzes this loop and determines that 'a' is never modified within the loop body.
       To save execution time, it applies condition optimization:

       1. while (a > 0)                 // Original condition
       2. while (1 > 0)                 // Substitutes the known cached constant
       3. while (true)                  // Reduces to an infinite loop

       The Danger: If an external hardware trigger or an Interrupt Service Routine (ISR)
       modifies the value of 'a' in RAM to 0, this loop will NOT exit. The processor
       is completely blind to the RAM change because it is evaluating the optimized 'true' condition.
    */
    while (a > 0) {
        // Waiting for a hardware state change
    }
}

// ==========================================
// Arithmetic Optimization Example
// ==========================================
void arithmetic_optimization() {
    int a = 0;

    /*
       Similarly, compilers will collapse redundant operations.
       Instead of executing three distinct add instructions, the compiler rolls
       them into a single, mathematically equivalent operation to save CPU cycles.
    */

    // a = a + 1;
    // a = a + 1;
    // a = a + 1;

    a = a + 3;                          // Optimized output generated by the compiler
}

// ==========================================
// 2. The Solution: The 'volatile' Keyword
// ==========================================
void volatile_usage() {
    /*
       Applying the 'volatile' Type Qualifier (TQ) strips the compiler of its optimization privileges for this variable.
       It strictly forbids register caching and arithmetic folding.
    */
    volatile int a = 1;

    /*
       The processor is now forced to execute a physical memory read from RAM on every single iteration.
       If an external interrupt (like a timer or GPIO pin) changes 'a' to 0 in RAM,
       the loop will immediately detect the change and break.
    */
    while (a > 0) {
        // Loop correctly responds to external memory changes
    }
}

```

### Engineering Application: Hardware Abstraction Layers

- Understanding the physical memory behavior detailed in the `volatile` model
  above is the importance of embedded C programming, particularly when
  constructing peripheral drivers or memory-mapped hardware abstractions.

- When you declare a pointer to a specific memory address (like a configuration
  register for a microcontroller), it **must** be declared as `volatile`. If it
  isn't, the compiler will assume the hardware register acts like normal RAM and
  optimize out consecutive reads/writes.

- Combining this with our earlier data structures, a robust hardware mapping
  usually looks like this:

```c
// Mapping a bit-field structure to a volatile hardware register
typedef struct {
    unsigned int ENABLE  : 1;
    unsigned int MODE    : 3;
    unsigned int FLAG    : 1;
    unsigned int         : 27; // Anonymous padding
} PeripheralControl_t;

// The pointer targets a specific memory address and uses 'volatile'
// to ensure every read/write hits the physical silicon.
#define PERIPHERAL_CTRL (*((volatile PeripheralControl_t *)0x40021000))

void enable_hardware() {
    // A direct write to the hardware register
    PERIPHERAL_CTRL.ENABLE = 1;

    // The compiler is forced to read the physical register
    // repeatedly until the hardware clears the flag.
    while (PERIPHERAL_CTRL.FLAG != 0) {
        // Wait for hardware to acknowledge
    }
}
```

### Advanced volatile Usage, Compiler Optimization, and Hardware Pointers

```c
#include <stdint.h>

// ==========================================
// 1. Core Mechanics of 'volatile'
// ==========================================
/*
   The volatile main job is to disable the optimization of that variable.
   Specifically, the compiler turns off optimizing the read-write operation on variable.

   Why do compilers optimize this by default?
   With higher optimization compiler might removed the code to read the data from register
   because reading data from SRAM require higher clock cycle which increase power consumption.
*/

void volatile_mutability() {
    // Standard Volatile
    volatile int i = 10;
    // User and External factor both can change the 'i' value.
    i = 20;                                     // Valid program assignment

    // Const Volatile (Read-Only Hardware Registers)
    const volatile int j = 10;
    // User not able to change 'j' value directly.
    // External factor able to change the 'j' value.
    j = 20;                                  // X Compile Error: Assignment of read-only variable
}

// ==========================================
// 2. When to Use volatile?
// ==========================================
/*
   In embedded software and hardware abstraction layers, 'volatile' is strictly
   required in three primary scenarios:
   1. For dealing with Memory mapped peripheral registers.
   2. RTOS multithreaded application (when variables are shared across threads/tasks).
   3. For global variables used between main code and ISR code (Interrupt Service Routines).
*/

// ==========================================
// 3. Pointer Variations for Hardware Mapping
// ==========================================
void hardware_pointer_variations() {
    // 1. Volatile Data
    uint8_t volatile data;                      // The data itself can change unexpectedly.

    // 2. Pointer to Volatile Data
    // This is used to read any memory mapped register.
    uint8_t volatile *pStatusReg;

    // 3. Volatile Pointer to Standard Data
    // The address the pointer holds can change unexpectedly, but the data at the address won't.
    uint8_t * volatile pStatusReg2;

    // 4. Volatile Pointer to Volatile Data
    // Both the pointer's address and the underlying data can change externally.
    uint8_t volatile * volatile pStatusReg3;

    // ------------------------------------------
    // Real-World Fixed Hardware Addresses
    // ------------------------------------------

    // 5. Constant Pointer to Volatile Data
    // The pointer permanently targets a specific memory address (e.g., 0x40000000),
    // and the peripheral at that address updates the data autonomously.
    uint8_t volatile * const pReg1 = (uint8_t *)0x40000000;        // (Typed cast matched to standard uint8_t)

    // 6. Constant Pointer to Constant Volatile Data
    // Used for reading read-only data buffer or address which is prone to unexpected change.
    // The program cannot write to this address, but the hardware will update it (e.g., a hardware status or ADC result register).
    uint8_t const volatile * const pReg2 = (uint8_t *)0x40000000;
}
```
