# Dynamic memory allocation

- Allocating memory at run time is called D.M.A.

```c
// Dynamic Memory Allocation Core API from "image_a4b3fd.png"

#include <stdlib.h>      // Provides the pre-defined fn.

// ==========================================
// Pre-defined Functions in stdlib.h
// ==========================================
/*
   Dynamic memory management in C relies on four fundamental functions
   to allocate, resize, and release heap memory at runtime.
*/

void dynamic_memory_overview() {
    malloc( - )
    // Allocates a single block of memory of a specified size (one
    // argument). The allocated memory is uninitialized and
    // contains residual garbage values.

    calloc( - , - );
    // Allocates memory for an array of elements, taking two arguments
    // (element count and size). Crucially, it initializes all
    // allocated bytes to zero before returning the pointer.

    realloc( - , - );
    // Resizes a previously allocated memory block, taking two arguments
    // (original pointer and new size). Existing data is preserved
    // up to the lesser of the new and old sizes. If the block must be
    // moved to find contiguous space, it copies the data automatically.

    free( - );
    // Releases the dynamically allocated memory back to the heap, taking a
    // single argument (the pointer). Failing to call this
    // function on allocated memory results in memory leaks.
}
```

## malloc()

```c
// Implementation of malloc()

#include <stdio.h>
#include <stdlib.h>

void malloc_implementation() {
    int *p, i;

    // We are requesting heap manger to allocate 10 (size) Bytes of memory
    // on heap segment.
    // Signature: void * malloc(size_t size)

    // If memory is allocated then heap manager will return starting address allocated
    // block. The void* is explicitly cast to (int*).
    p = (int *) malloc(10);

    // Assuming the starting address returned is 500, and int is 2 bytes.
    for(i = 0; i < 5; i = i + 1) {
        // Prints the uninitialized memory contents (GV: Garbage Values)
        printf("%d ", *(p + i));
    }
}

/*
===========================================================================
Memory Layout and Segments ASCII Diagram
===========================================================================

Program Segments:                   Pointer and Heap Mapping:
+-------------+
|     st      | <--- Stack          Stack:
+-------------+                     +------+
|    heap     | <--- Heap           |  p   | ---> Holds Address 500
+-------------+                     +------+
|     DS      | <--- Data Sec
+-------------+                     Heap Block (10 Bytes Allocated):
|    Bss      | <--- BSS Sec        +------+------+------+------+------+
+-------------+                     |  GV  |  GV  |  GV  |  GV  |  GV  |
|     RO      | <--- Read Only      +------+------+------+------+------+
+-------------+                     ^      ^      ^      ^      ^
|     CS      | <--- Code Sec       500    502    504    506    508
+-------------+                     (Assuming 2-byte integers)
*/
```

- The `malloc` function returns a generic `void *` pointer. This
  must be explicitly cast to the appropriate data type pointer, such as
  `(int *)`, to allow correct pointer arithmetic and data access.

- As shown in the memory map, the heap manager allocates a contiguous block
  of 10 bytes. Because `malloc` does not initialize this memory,
  iterating through and printing the addresses (500, 502, 504, 506, 508)
  yields unpredictable Garbage Values (GV).

### Handling malloc() Failures and Memory Initialization

```c
#include <stdio.h>
#include <stdlib.h>

void malloc_failure_handling() {
    int *p, i;

    // We are requesting heap manger to allocate 10 (size) Bytes of
    // memory on heap segment.
    p = (int *)malloc(10);               // Explicit cast (Best practice)
    p = malloc(10);                      // Implicit cast (Valid in C)

    // ==========================================
    // Memory Allocation Failure (MAF) Check
    // ==========================================
    // if memory is allocated then hm will return starting address
    // allocated block (on SUCCESS)
    // if memory is not allocated then hm will return NULL
    // (ON Failure)

    if (p == NULL) {
        printf("MAF");                      // MAF output if failed
        return;                             // Exit to prevent crashing
    }

    // ==========================================
    // Initializing the Allocated Memory
    // ==========================================
    for (i = 0; i < 5; i = i + 1) {
        // Populating the heap block with data: 10, 20, 30, 40, 50
        *(p + i) = (i + 1) * 10;
    }
}

/*
===========================================================================
Memory Mapping After Initialization
===========================================================================

Pointer in Stack:                   Populated Heap Block:
+------+                            +----+----+----+----+----+
|  p   | ---> Holds Address 500 --> | 10 | 20 | 30 | 40 | 50 |
+------+                            +----+----+----+----+----+
[ 500 ]                             ^
                                    500
*/
```

- Always verify that the heap manager successfully allocated the memory
  by checking if the returned pointer is `NULL`.

- If a system is out of memory (Heap Exhaustion), dereferencing a `NULL` pointer
  will cause a fatal segmentation fault.

- Once validated, the allocated memory can be safely accessed and
  modified using standard pointer arithmetic, as demonstrated by the
  assignment loop.

### Hard vs. Soft Coding Allocation Sizes

```c
#include <stdio.h>
#include <stdlib.h>

// ==========================================
// 1. The Danger of Hard Coding
// ==========================================
void hard_coded_allocation() {
    int *p;

    // Hard coding the allocation size (e.g., 10 bytes) is dangerous.
    // It assumes an integer is a fixed size, which ruins portability.
    p = malloc(10);                     // hard code
}

// ==========================================
// 2. Platform-Independent Soft Coding
// ==========================================
void soft_coded_allocation() {
    int *p;
    int n;

    // Request the desired number of elements dynamically.
    printf("enter no.of elements");
    scanf("%d", &n);

    // Using (n * sizeof(int)) guarantees cross-platform safety.
    // It calculates the exact byte requirement at compile time.
    p = malloc(n * sizeof(int));        // Soft Code
}

/*
===========================================================================
Soft Coding Portability (ASCII Visualization)
===========================================================================
If n = 5 elements:

16-bit Architecture (sizeof(int) = 2 bytes):
+----+----+----+----+----+
| 2B | 2B | 2B | 2B | 2B | -> malloc(10) is dynamically generated.
+----+----+----+----+----+

32-bit/64-bit Architecture (sizeof(int) = 4 bytes):
+------+------+------+------+------+
|  4B  |  4B  |  4B  |  4B  |  4B  | -> malloc(20) is dynamically generated.
+------+------+------+------+------+
*/
```

- By leveraging `sizeof()`, the compiler evaluates the physical memory footprint
  required by the target CPU architecture before passing the final calculated
  integer to the heap manager.

### Memory Deallocation with free()

```c
#include <stdlib.h>

// ==========================================
// Releasing Allocated Memory
// ==========================================
void memory_deallocation() {
    int *p;

    // Allocate 10 bytes on the heap and store the base address.
    p = malloc(10);                     // (ok) Allocation

    // Release the memory block back to the heap manager.
    // Failing to execute this step results in memory leaks.
    free(p);                            // (ok) Deallocation
}

1. free(p) targets address 500 and releases the 10-byte block.
2. The pointer 'p' is crossed out because its target memory is gone,
```

### Memory leak

- Allocating some memory on heap and if your are unable to access that memory is
  called memory leak

### Preventing Memory Leaks

```c
#include <stdlib.h>

// ==========================================
// 1. The Problem: Memory Leak (ML)
// ==========================================
void memory_leak_example() {
    int *p;

    // Allocates 10 bytes at address 500. 'p' holds 500.
    p = malloc(10);

    // Allocates 20 bytes at address 600. 'p' is overwritten.
    p = malloc(20);

    // The original 10-byte block at 500 is now completely lost.
    // This causes a Memory leak.
}

// ==========================================
// 2. Solution 1 (Sol1): Pointer Backup
// ==========================================
void solution_one_backup() {
    int *p, *t;

    p = malloc(10);                   // 'p' gets address 500.
    t = p;                            // Backup the address 500 into 't'.

    p = malloc(20);                   // 'p' gets address 600.
    // Both blocks (500 and 600) remain accessible and can be freed.
}

// ==========================================
// 3. Solution 2 (Sol2): Free Before Reassign
// ==========================================
void solution_two_free() {
    int *p;

    p = malloc(10);                   // 'p' gets address 500.
    free(p);                          // Release block 500.

    p = malloc(20);                   // 'p' safely gets address 600.
}

/*
===============================================================================
Memory Leak Mechanisms and Solutions
===============================================================================

The Problem: Memory Leak
  p
+-----+      +-----------+
| 500 | -/-> | 10B Block | -> Memory leak.
+-----+      +-----------+
  | 600        ^ 500
  v
+-----------+
| 20B Block |
+-----------+
  ^ 600

Sol1: Pointer Backup
  p            t
+-----+      +-----+      +-----------+
| 600 |      | 500 | ---> | 10B Block | (500) -> Safe
+-----+      +-----+      +-----------+
  |
  v
+-----------+
| 20B Block | (600)
+-----------+

Sol2: Free Before Reassignment
  p
+-----+      +-----------+
| 500 | ---> |///////10B | -> Freed
+-----+      +-----------+
  | 600      ^ 500
  v
+-----------+
| 20B Block | (600)
+-----------+

Pointer States Summary:
1. Wild Pointer (Uninitialized pointer / pointer to unreserved memory)
2. NULL Pointer (Points to nothing / pointer to 0th location)
3. dangling Pointer (Points to freed memory / pointer to dead memory)
4. memory leak (Lost access to allocated memory)
*/
```

### Common runtime errors associated with dynamic memory allocation

- Errors specifically focusing on dangling pointers, null pointer assignments
  and double-free errors.

#### Dangling Pointers & Segmentation Faults

```c
void main() {
    int *p;
    p = malloc(10);
    free(p);
    *p = 10; // => R.T.E: Segmentation fault

```

- A pointer `P` on the stack holds the address `500`, pointing to a 10-byte
  block on the heap. When `free(p)` is called, the memory at `500` is returned
  to the system, but the variable `P` still holds the address `500`.

- Attempting to write to this dangling pointer (`*p = 10`) accesses unallocated
  memory, triggering a Segmentation Fault.

#### Null Pointer Dereference

```c
    p = NULL;
    *p = 10; // => R.T.E: Null Pointer Assignment
}

```

- Dereferencing a `NULL` pointer guarantees a predictable runtime error.
- In embedded environments, catching a null pointer dereference is generally
  preferable to the silent memory corruption caused by writing to a dangling
  pointer.

#### Double Free Error

```c
int *p;
p = malloc(10);
free(p);
free(p); // R.T.E: Segment fault / double free Error

```

- Calling `free()` a second time on an already freed address corrupts the
  heap manager's internal data structures, leading to a crash.

#### Recommended Best Practice

```c
free(p);
P = NULL;

```

- Setting the pointer to `NULL` immediately after freeing it ensures that any
  accidental subsequent access triggers a clear null pointer exception rather
  than memory corruption.
- Furthermore, standard C libraries safely ignore `free(NULL)`, meaning this
  practice actively prevents the double-free error.

### Deallocating Stack Variables and Hidden Heap Headers

```c
#include <stdlib.h>

// ==========================================
// 1. Invalid Free on Stack Memory
// ==========================================
void invalid_free_stack() {
    int a = 10;
    int *p = &a;

    /*
       The variable 'a' is allocated on the Stack, not the Heap.
       Calling free(p) attempts to return a Stack address to the heap manager,
       which results in a Runtime Error (R.T.E).
    */
    free(p);                                // R.T.E
}

/*
===============================================================================
2. How free() Knows the Allocation Size
===============================================================================

Notice that free(p) takes only the pointer as an argument; you do not tell it
how many bytes to free. The heap manager tracks this autonomously using a
hidden "header" block placed immediately before the returned address.
[NOTE: This is just theory but actual implementation will change by machine to
       machine]
*/
// Case 1: 10 Bytes Allocated
  int *p;
  p = malloc(10);
  free(p);
/*
  Stack: P [ 500 ] ---> Heap: [ 10 ] [ ----- 10 Bytes ----- ]
                              ^
                          size(header) placed before address 500.
*/

// Case 2: 20 Bytes Allocated
  int *p;
  p = malloc(20);
  free(p);
/*
  Stack: P [ 600 ] ---> Heap: [ 20 ] [ ---------- 20 Bytes ---------- ]
                              ^
                          Header at address (600 - header_size) stores '20'.
*/

// Case 3: Character Pointer (Type Agnostic)
  char *p;
  p = malloc(10);
  free(p);
/*
  Stack: P [ 700 ] ---> Heap: [ 10 ] [ ----- 10 Bytes ----- ]

When free(p) is called, the heap manager looks at the memory immediately
preceding the address held in 'p' to read the size (header) and knows exactly
how many bytes to release back to the system.
*/
```

## realloc()

```c
// Resizing Memory with realloc()

#include <stdlib.h>

// ==========================================
// 1. The Manual Reallocation Process
// ==========================================
void manual_reallocation() {
    int *p, *t, i;

    // Initial allocation of 10 bytes and population of data.
    p = malloc(10);
    for(i = 0; i < 5; i = i + 1) {
        *(p + i) = (i + 1) * 10;
    }

    /*
       Manual steps to resize the memory block from 10 to 20 bytes:
       1. Backup the old pointer to 't'.
       2. Allocate a new, larger block of 20 bytes to 'p'.
       3. Copy the old data from 't' into the new 'p' block.
       4. Free the old block at 't' and set it to NULL.
    */
    t = p;
    p = malloc(20);
    for(i = 0; i < 5; i = i + 1) {
        *(p + i) = *(t + i);
    }
    free(t);
    t = NULL;
}

// ==========================================
// 2. The realloc() Shortcut
// ==========================================
void using_realloc() {
    int *p = malloc(10);

    // => P = realloc(P, 20); replaces the entire manual block above.
    // It dynamically handles malloc, calloc, or realloc internally.
    p = realloc(p, 20);
}

/*
===============================================================================
Memory Reallocation Visualization[cite: 20, 21]
===============================================================================

  t [ 500 ]
        |          10 Bytes
   P    +------> [ 10 | 20 | 30 | 40 | 50 ]
 [ 500 ]/        500
   600  \
         \
          \----> [ 10 | 20 | 30 | 40 | 50 |  GV GV  ]
                 600                        10B

Notice that when resizing to 20 bytes, the old data is preserved, while
the newly allocated 10-byte extension contains Garbage Values (GV).
*/

// ==========================================
// 3. Downsizing and Freeing via realloc()
// ==========================================
void realloc_special_cases() {
    // Case A: Downsizing memory
    int *p = malloc(10);
    p = realloc(p, 6);                          // Shrinks block to 6 bytes

    // Case B: realloc as free()
    int *p2 = malloc(10);

    // Passing 0 as the size acts exactly like calling free().
    p2 = realloc(p2, 0);                        // -> free(p);
}
```

## Why Dynamic memory allocation

- There is no concept called ~~Compile time~~ Time memory allocation.

```c
// Compile Time vs Runtime Allocation

#include <stdio.h>
#include <stdlib.h>

// ==========================================
// 1. Compile Time / Static Memory Allocatn
// ==========================================
void static_memory_allocation() {
    /*
       During compilation, the compiler scans for variable declarations
       and allocates stack space regardless of runtime conditions.
    */

    if (2 > 3) {
        int a;                              // Allocates 2 bytes
    }

    if (3 > 2) {
        int a;                              // Allocates 2 bytes
    }
}

// ==========================================
// 2. Scope Bypass with Goto
// ==========================================
void scope_bypass_goto() {
    int a = 10;
    goto inside;

    {
        // The goto statement jumps over the initialization of this
        // inner-scope variable. Memory is allocated, but not set.
        int a = 20;

    inside:
        // Because initialization was bypassed, printing 'a' yields GV.
        printf("%d", a);
    }
}

/*
===============================================================================
Goto Execution Flow Visualization
===============================================================================

  int a=10;              a [   ] 10
  goto inside; ----.
  {                |
    int a=20; <----|-------- [ GV ]
    inside: <------'
    printf("%d",a);
  }

  GV
*/

// ==========================================
// 3. Runtime Dynamic Memory Allocation
// ==========================================
void dynamic_runtime_allocation() {
    /*
       Unlike static allocation, dynamic allocation evaluates at runtime.
       If the condition is false, the malloc function never executes.
    */

    if (2 > 3) {
        malloc(10);                         // 0B (0 Bytes allocated)
    }

    if (3 > 2) {
        malloc(10);                         // 10B (10 Bytes allocated)
    }

    // ------------------------------------------
    // Standard Execution Output comparison
    // ------------------------------------------

    if (2 > 3) {
        printf("hello");                    // no o/p
    }

    if (3 > 2) {
        printf("hello");                    // hello
    }
}
```

## When memory allocates for variables

- In C there is No concept called Compile time memory allocation.
- Memory will allocate after the compilation and before the execution of main function.

```c
Example:
int a = 5;
void main()
{
  int a = 10;
  goto inside;
  {
    int a = 20;
    inside:
    printf("%d", a);
  }
}
```

- What is the output?
  - Answer: Garbage value

- REASON:
  1. compiler will compile the code from top to bottom during this time compier will
     note down the scope and size of each variable.Here compiler noted the
     variable 'a' is at two diffrent scope and size of variables.
  2. After all steps are over and Now this point is before of main function execution
  3. Here memory is allocated and initialized with their default value. Here global
     variables are initialized with 0 and local variables are initialized with G.V
  4. Now main function executing
  5. int a = 10 is executed and execution flow moved to inside lable.
  6. Now print function looks for vairable 'a' and found at its scope so it picks
     inner block variable 'a' initialized with G.V

- Allocation of memory at run time on Heap is called dynamic memory allocation.
- Allocation of memory after compile time and before main function execution on
  stack is called static memory allocation.
